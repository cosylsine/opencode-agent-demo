## 本次提供什么

- 用户自行注册、登录、退出、修改密码；管理员维护账号、停用和重置密码。重置后必须设置新密码。
- Skill、智能体支持私有／公共、草稿、发布、固定版本、归档、恢复和删除。创建时即可选择可见范围，发布后也能修改；公共资源只有使用权，公共 Skill 可以阅读和引用，原内容只由创建者修改。
- 17 项办公工具可直接操作，也可由智能体通过 MCP 调用。保留原有 9 项：文档读取、表格读取、表格处理、表格校验、数值计算、日期计算、Word 生成、表格生成、文本导出；新增 8 项见下表。工具中心以卡片展示用途、分类和状态，支持分类筛选与搜索；点击“开始使用”进入表单，返回时保留筛选条件和浏览位置。
- 对话式任务包含附件、多轮处理、真实执行阶段、取消、历史任务、重命名、删除和产物下载。刷新页面可回到原任务。
- 预置通用助手、工作记录转周报、材料完整性检查和表格汇总四个助手。通用助手可直接问答、写作和整理需求，无需先配置 Skill；新对话统一保存在“我的任务”。
- “接待对话”不再占据一级导航。旧记录从“我的任务 → 旧版接待记录”搜索和只读查阅，仍按账号隔离；原链接 `#chat` 也进入该查阅页。
- Monitor 和 B 回路保留原有业务流程，本轮没有向 Monitor 添加对话或检查能力。持续采样仍是公共只读输入，定时检查配置仍由管理员维护。
- 主侧栏整体滚动，支持收起、展开和拖动调宽，并记住设置；账号入口固定在底部。所有页面统一显示 OpenCode 标识，业务运行历史仍保留自己的滚动和小屏抽屉。

输入支持 DOCX、XLSX、CSV、TXT、Markdown、PDF、ZIP；ZIP 只作为打包附件，不解压读取。输出支持 DOCX、XLSX、CSV、TXT、Markdown、整理后的 PDF 和 ZIP。不含 OCR、图片理解、PPTX、Word 转 PDF、任意脚本和外网访问。Excel 读取已保存的公式缓存，不重新计算完整 Excel 公式。

## 已有服务器升级

所有命令在服务器原部署目录执行。先确保旧版备份可用。更新盘目录为 `delivery/office-v1-20261018/disc-01/`，盘上包含 `START-HERE.txt`、校验清单和 `patch-files/`。它是更新盘，不能代替首次安装所需的完整部署包。

1. 用原部署目录中的旧脚本备份：

   ```bash
   sudo bash deploy.sh backup
   sudo bash deploy.sh stop
   OFFICE_UPDATE_STAMP=$(date +%Y%m%d-%H%M%S)
   sudo tar -czf "backups/code-before-office-$OFFICE_UPDATE_STAMP.tar.gz" deploy.sh Dockerfile .dockerignore build source config/demo.env.example
   sudo cp images/offline-images.tar.gz "backups/images-before-office-$OFFICE_UPDATE_STAMP.tar.gz"
   ```

2. 将光盘的 `patch-files/` 全部复制到原部署目录，包含隐藏文件。不要删除原目录，不覆盖现场 `config/demo.env`、`data/` 和 `backups/`。随后执行：

   ```bash
   chmod 755 runtime/ripgrep/rg
   bash deploy.sh verify
   sudo bash deploy.sh load
   sudo bash deploy.sh init-admin
   ```

   初始化命令交互输入管理员用户名和两次密码，不会显示密码。服务必须停止；已有管理员时不会重复创建。

3. 启动并等待模型和采样就绪：

   ```bash
   sudo bash deploy.sh up
   sudo bash deploy.sh check --wait 300
   ```

4. 浏览器刷新原地址，例如 `http://10.70.100.220:3000`。先用初始化的管理员登录，再由成员自行注册。

离线包包含新标签的应用及办公依赖镜像：

```text
opencode-agent-demo:20261018-office-amd64
opencode-agent-demo-runtime:20261018-office-amd64
```

本包中的镜像已经构建，导入后无需再次 rebuild。后续修改源码再运行 `sudo bash deploy.sh rebuild`，仍以 `--network none` 构建。

## 用户使用顺序

1. 在办公工具中先用真实材料试用单项操作。
2. 在 Skill 中心填写用途、输入要求、执行步骤、异常处理、输出要求，选择可见范围和依赖工具，保存并发布。选择公共但尚未发布的草稿仍然只有自己可见。
3. 点击“用此 Skill 创建智能体”或从智能体中心创建，确认可见范围、技能版本、工具、开场白和示例问题，发布后开始使用。公共智能体引用的 Skill 也必须为公共；权限、内容和发布版本会在同一次保存中提交，失败不留下半成品。
4. 上传附件并描述任务。每项任务绑定一个智能体版本，可继续修改已有结果；更换智能体会创建新任务。
5. 分享前先把依赖 Skill 设为公共，再把智能体设为公共。其他用户拥有各自的会话、文件和结果，不继承创建者的数据。

创建与编辑页采用单列表单，主工作区统一滚动，不再在右侧展示完整能力目录。配置页只显示已绑定的 Skill 和已选工具；点击“选择 Skill”或“选择工具”进入专门的选择界面，支持搜索、分类、仅看已选和分页，每页最多 8 项，仍使用主页面滚动。确认后返回原位置，取消不改变已选项，未保存的正文和权限设置会保留；Skill 必需工具自动选择且不能单独取消。

正文输入框随内容增高，适用条件、输入输出要求、开场白和示例问题等可选设置按需展开。手机与电脑使用相同的滚动方式。编辑和选择界面的标题栏吸顶后紧贴工作区顶部；字段滚动定位会预留标题栏的实际高度。本轮交互调整与验收见 [编辑页滚动优化](verification/editor-scroll-20261019/RESULTS.md)，后续修复见 [标题栏吸顶错位修复](verification/editor-header-fix-20261019/RESULTS.md)。

发布后可以在编辑页修改可见范围并保存，也可在详情中切换私有／公共，无需为权限变化单独发布新版本。修改内容后需要发布新版本，已有任务继续绑定原内容版本。

归档用于暂时停用并保留配置、发布版本和引用，创建者可查看及恢复；其他用户无法在列表、详情、新任务或 Skill 引用中继续访问和使用。收回公共权限同样阻止其他用户后续执行。正在执行的任务会在下一次工具调用和提交答复前重新检查资源权限，权限失效后不再继续调用或提交答复；已保存的历史记录保留。工具由管理员停用时，后续调用会明确报告不可用。

删除用于永久移除自己创建的资源及其全部发布版本，界面会先要求确认。旧任务、消息、附件和产物不随资源删除，相关旧任务仅供查阅。仍有任务执行或排队的智能体不能删除；仍被任何智能体草稿或发布版本（包括已归档智能体）引用的 Skill 不能删除，需先删除关联智能体，或者使用归档停用。平台内置资源不可删除。删除的导入资源不会在重启时重新出现。

通用助手的办公工具为可选能力：停用个别工具不影响普通问答，每轮执行只授予当前仍启用的工具。

## 限制与失败处理

- 默认每个附件 20 MiB、每次消息最多 5 个。可在现场配置新增 `OFFICE_MAX_FILE_BYTES=20971520`、`OFFICE_MAX_ATTACHMENTS=5`（数量范围 1–20），重新 up 生效。
- 原业务 JSON 请求上限仍为 32 KiB；办公资源、消息、工具参数采用有界的 2 MiB 请求上限，上传单独按流量限制。
- 默认同时执行一项办公任务，其他任务排队；每轮总时限 10 分钟、最多 24 次工具调用。文件工具在受限子进程执行，单次最长 60 秒。
- 表格支持最多 100000 行、200 列，生成 Word 附表最多 5000 行。大表先汇总，预览过大时减少返回内容，原始数据和计算结果不变。
- 服务重启将正在运行的办公任务标为中断，不会自动重发状态不明的模型请求；可检查已有结果再手动重试。
- 生成 Word 时，正文可放入 `content`（纯文本或 Markdown）或 `paragraphs/sections`；只有标题或空模板会被拒绝。工具调用中的未知参数会明确报错，不能静默忽略。修复与验证记录见 [Word 正文修复](verification/docx-body-fix-20261018/RESULTS.md)。
- 文档读取不支持扫描 PDF 的文字识别；PDF 页面工具可处理扫描件。加密 PDF、缺失字段、无公式缓存等会给出明确说明。

## 模型和完整办公验收

B 回路多轮调优已改为只通过只读 MCP 提供一次业务历史，保留全部轮次和四工况指标。指标在模型上下文中以 8 位有效数字表示，数据库和接受判定仍用原始精度；拒绝记录不再携带完整长篇模型解释。无需调大 Qwen3.8-27B 的窗口，默认 `VLLM_CONTEXT=32768`、`VLLM_MAX_OUTPUT=8192` 继续适用，模型地址和密钥仍由现场配置提供。

后端现负责在推理前校验并预加载两项技能，通过 MCP 读取一次完整授权上下文，再将准备好的内容提供给模型；模型只提交结构化候选，不再自行加载技能或读取业务数据，B 回路调用凭据不进入模型提示词。每份结果必须通过请求关联、上下文回执及结构化类型检查。已确认的准备失败或无效模型输出在同一轮内最多尝试三次，不增加仿真次数或未改善计数；状态不明的请求不自动重发。程序约束验收见 [B 回路流程修复](verification/b-loop-workflow-20261019/RESULTS.md)。

上下文超限、会话自动压缩和已结束但缺少结构化输出分别明确报错；后端继续要求原请求关联和有效 `StructuredOutput`，不从普通文本提取候选，也不自动重发不明请求。既有失败记录与最佳仿真参数保留，应用修复后新建调优。验证记录见 [B 回路 32K 上下文修复验收](verification/b-loop-context-20261019/RESULTS.md)。

先做原有模型协议检查，再做完整任务：

```bash
sudo bash deploy.sh probe-model
sudo bash deploy.sh probe-agent
sudo bash deploy.sh smoke-office
```

`smoke-office` 交互输入一个可用账号。脚本创建私有验收 Skill、智能体、任务及测试 Excel，然后用实际模型完成两轮“读取 → 校验 → 按人员汇总 → 生成 Word”，下载并重新打开产物，核对张三的汇总工时为 5，检查第一轮文件仍可下载。

报告位于 `data/var/backend/office-acceptance.json`，包含工具阶段、文件 ID、摘要和核对结果，不含账号密码。原业务验收仍可用 `sudo bash deploy.sh smoke`，现在也需要登录账号。

首次交付的 TEST 协议验收只证明真实 OpenCode、MCP、后端和文件工具之间的链路。后续已在制作机接入用户指定的 tailnet `.7` 真实 Qwen3.8-27B，相关验证与统一界面记录见 [verification/ui-unification-20261018/RESULTS.md](verification/ui-unification-20261018/RESULTS.md)。所内升级后仍须按现场服务地址重新验收；首次基础回归见 [verification/office-v1/RESULTS.md](verification/office-v1/RESULTS.md)。
