# 修复内网访问 403：服务器部署，Windows 电脑只用浏览器

适用版本：本目录中的 `opencode-agent-demo:20261013-amd64` 离线部署包。编写日期：2026-10-14。

**2026-10-18 同步状态：**当前项目已应用第 4–7 节和第 10.5.3–10.5.5 节的源码补丁，无需对当前副本重复替换。配置及模板已设置服务器 `10.70.100.220`、网页端口 `3000`、OpenCode 端口 `14097`、vLLM 端口 `4625`；客户端白名单已确认配置为 `10.70.0.0/17`。以下保留原手工修复、排查与回退步骤，其中 `192.168.10.*` 仍为示例地址。同步与本地验证记录见 [LAN-SYNC.md](verification/LAN-SYNC.md)。

本次同步保留了原 `SHA256SUMS`，另用 `verification/LAN-SYNC-SHA256SUMS` 记录修改/新增文件；`deploy.sh verify` 校验明确标识的同步版本。当前项目随后已实际离线重建并替换应用镜像归档，保留原应用标签；使用当前归档时 `load` 后即可配置并 `up`，使用旧光盘/旧归档手工修复时仍需 `rebuild`。见 [重建记录](verification/REBUILD.md)。旧 DVD 分卷仅用于运输，完成还原、导入和验收后即可删除；重新制作时使用更新后的 README。

**重建验收补充：**实际工具调用发现，`source/opencode.json` 原有的内部 `18000` 地址会覆盖启动器生成的 `3000` 地址。当前项目已将该配置改为环境变量引用，并在 `source/scripts/launch_opencode.py` 中保证默认值与传入值一致。若现场只能通过就绪/普通聊天检查、Monitor 工具仍报 401，应核对 MCP 进程实际使用的内部地址，不能只看生成的配置文件。

目标：服务部署在 Linux 服务器上，同内网的 Windows 电脑通过 **`http://服务器内网IP:3000`** 使用服务。Windows 端只输入网址、刷新页面和使用应用；所有命令、文件编辑、重建和排查均在服务器进行。

以下是原版部署包的操作手册；尚未修复的服务器需要执行相应修改。403 修复涉及四个文件：`config/demo.env`、`build/runtime.py`、`source/apps/orchestrator/main.py`、`source/apps/dashboard/index.html`。若 403 已解决，但 Chrome 86 内核的 360 浏览器仍然白屏，直接阅读第 10.5.1–10.5.7 节（2026-10-15 补充）；该兼容补丁另涉及前端构建配置和两个样式文件。

执行顺序：第 1–2 节确认现场状态；第 3 节备份；第 4–7 节逐项修改；第 8 节重建并在服务器自测；第 9 节进行浏览器验收。有异常查第 10 节，需要恢复服务查第 11 节。

## 0. 先明确当前问题和操作约定

目前已知：其他电脑使用 360 浏览器，访问服务器 IP 的 3000 端口时，一打开网址就只看到 403。

源码已确认三个限制：后端只监听回环地址；API 默认拒绝非回环客户端；启动程序把网页 Origin 固定为回环地址。它们必须一起调整，才能支持内网直连。

但**当前首页处理函数没有返回 403 的鉴权分支**。所以首屏 403 的响应者还未确定，可能涉及其他服务、代理、网络访问控制或现场版本差异。按下面步骤先留存证据，再修改应用；不要把所有 403 都当作 CSRF。

操作约定：

- 标记 **[服务器终端]** 的命令，只在 Linux 服务器执行。命令块不包含命令提示符，逐块复制；出现错误时先按该步的分支处理。
- 标记 **[Windows 浏览器]** 的内容，只需输入网址。其他电脑上的 `127.0.0.1` 指向其他电脑自己，不是服务器。
- 文中 `192.168.10.20`、`192.168.10.0/24` 都是示例，必须换成现场实际值。
- 不删除 `data/`，不重新安装 Docker，不重新导入模型。应用的小补丁可以使用包内已有依赖离线重建。
- 本方案用于可信内网演示：白名单内客户端共用现有的演示身份和操作权限。客户端网段白名单控制 API 访问；首页和静态资源仍可加载，网络入口范围由服务器防火墙控制。

### 2.2 用容器内已有 Python 做服务器直连检查

不要求服务器安装 curl 或宿主机 Python。下面使用当前应用容器内的 Python 和 httpx，并明确禁用代理。

**[服务器终端]** 整块复制；最后的 `PY` 单独一行，前面不要加空格：

```bash
sudo docker exec -i opencode-agent-demo python - "$FIX403_SERVER_IP" <<'PY'
import os
import sys
import httpx

port = int(os.environ.get("APP_PORT", "18000"))
print("容器当前 APP_PORT =", port)
with httpx.Client(trust_env=False, timeout=5, follow_redirects=False) as client:
    for host in ("127.0.0.1", sys.argv[1]):
        base = f"http://{host}:{port}"
        for path in ("/?lancheck=server-probe", "/api/v1/csrf-token"):
            try:
                response = client.get(base + path)
                print(base + path, "HTTP", response.status_code,
                      "server=", response.headers.get("server", "-"),
                      "mark=", response.headers.get("x-opencode-demo", "-"))
                if response.status_code >= 400:
                    print("错误正文:", response.text[:240])
            except httpx.HTTPError as exc:
                print(base + path, type(exc).__name__, str(exc))
PY
```

本脚本不输出 CSRF token 或业务密钥。`server=` 只是辅助线索，不能单独证明服务身份。`mark=` 在原版中是 `-`，实施本手册后会出现补丁标记。

预期的原版结果：回环首页和 `csrf-token` 为 200；服务器 IP 通常连接失败。若容器实际端口不是 3000，先记录，后面第 6 步统一设置为 3000。

| 现象 | 下一步 |
| --- | --- |

### 4.2 增加网页网络配置函数

找到 `def seed_directory(target, source):`，在它前面插入以下完整函数。`def web_settings` 与其他顶层 `def` 顶格对齐：

```python
def web_settings(app_port):
    bind_host = os.environ.get('APP_HOST', '127.0.0.1').strip()
    if bind_host not in ('127.0.0.1', '0.0.0.0'):
        raise ValueError('APP_HOST 只支持 127.0.0.1 或 0.0.0.0')
    origin = os.environ.get('DEMO_ORIGIN', '').strip() or f'http://127.0.0.1:{app_port}'
    parsed = urlsplit(origin)
    if (parsed.scheme != 'http' or not parsed.hostname
            or parsed.username is not None or parsed.password is not None
            or parsed.path or parsed.query or parsed.fragment
            or parsed.port != app_port):
        raise ValueError('DEMO_ORIGIN 必须是 http://服务器IP:APP_PORT，不带尾斜杠或路径')
    networks = tuple(
        ipaddress.ip_network(value.strip())
        for value in os.environ.get('DEMO_ALLOWED_CIDRS', '').split(',')
        if value.strip()
    )
    if bind_host == '0.0.0.0':
        if not networks:
            raise ValueError('内网访问必须配置 DEMO_ALLOWED_CIDRS')
        if parsed.hostname in ('127.0.0.1', 'localhost', '::1', '0.0.0.0'):
            raise ValueError('内网访问的 DEMO_ORIGIN 必须使用服务器真实内网地址')
    return bind_host, origin


```

### 5.3 保留内部接口限制，并给排查请求增加日志

找到从 `@app.middleware("http")` 开始、到紧接着的 `async def identity(...)` 之前的整个 `request_limits` 函数。只把这个中间件替换成下面完整内容，保留后面的 `identity` 函数：

```python
    @app.middleware("http")
    async def request_limits(request, call_next):
        peer = request.client.host if request.client else ""
        if request.url.path.startswith("/internal/") and peer not in loopback_peers:
            response = error_response("FORBIDDEN", "内部接口只允许本机访问", 403)
            response.headers["X-OpenCode-Demo"] = "lan-fix-20261014"
            return response
        length = request.headers.get("content-length", "0")
        try:
            if int(length) > 32768:
                return error_response("REQUEST_TOO_LARGE", "请求超过 32 KiB", 413)
        except ValueError:
            return error_response("VALIDATION_ERROR", "非法长度", 422)
        if request.method in ("POST", "PUT", "PATCH"):
            body = await request.body()
            if len(body) > 32768:
                return error_response("REQUEST_TOO_LARGE", "请求超过 32 KiB", 413)
        response = await call_next(request)
        response.headers["X-Content-Type-Options"] = "nosniff"
        response.headers["Referrer-Policy"] = "no-referrer"
        response.headers["Cache-Control"] = "no-store"
        response.headers["X-OpenCode-Demo"] = "lan-fix-20261014"
        if "lancheck" in request.query_params:
            logger.warning(
                "LAN_CHECK peer=%r host=%r ua=%r status=%s",
                peer, request.headers.get("host", "")[:120],
                request.headers.get("user-agent", "")[:200], response.status_code,
            )
        return response

```

作用：`/internal/` 仍只接受本机请求；正常响应带有补丁标记；带 `?lancheck=...` 的请求会在服务器日志中显示来源、Host、浏览器 User-Agent 和状态码。此日志不记录请求正文、Cookie 或认证 token。

## 10. 修复后不同现象怎么继续

### 10.1 Windows 首屏仍只有 403

按顺序核对，不再重复修改 CSRF：

1. 服务器执行第 2.1 节：确认实际监听者为应用，监听 `0.0.0.0:3000`。
2. 服务器执行第 2.2 节：确认服务器 IP 的首页为 200，且标记为 `lan-fix-20261014`。
3. Windows 只访问带新 `lancheck` 参数的网址；服务器观察对应日志。

| 服务器侧证据 | 下一步 |
| --- | --- |
| 直连服务器 IP 已是 403，缺少补丁标记 | 检查实际监听进程/其他转发服务，或确认是否仍运行旧镜像。 |
| 直连 200，浏览器请求没有到达应用 | 将目标 IP、TCP 3000、访问时间和“服务器直连正常、应用无对应请求”交给网络管理员，检查代理/PAC/访问控制。 |
| 日志有对应请求且首页 200，浏览器显示 403 | 检查返回链路上的代理、浏览器拦截或缓存，并确认日志与同一次带标记的 URL 对应。 |
| 日志显示首页 `/` 本身 403 | 保留该日志与直连错误正文。它不符合本手册补丁的首页逻辑，需要检查现场额外中间件、代理或运行版本。 |
| 日志中实际被拒绝的是 `/api/...` 或 `/internal/...` | 按 10.3、10.4 判断，区分首页与后续请求。 |

如果是统一代理策略，应由管理员集中允许目标服务器的 TCP 3000，或在现有 PAC/集中浏览器策略中为该站点设置直连例外。具体方式取决于现场策略，不能由应用代码改变请求到达之前的拦截；不要让每台 Windows 安装工具或关闭防护。

如果没有集中管理机制，而且浏览器代理设置也不允许调整，则仅修改服务器应用可能无法解决这一层问题，需要网络管理员协调。

- firewalld/UFW 都未运行但仍疑似主机过滤：管理员可在服务器只读查看 `sudo nft list ruleset` 或 `sudo iptables -S INPUT`，以现场已安装工具为准。不清空规则，不关闭整套防火墙。

### 10.5 首页 200，但空白、一直加载或按钮不工作

先检查服务器日志中 `/assets/...` 是否成功加载，以及第 8.3 节是否确认了 360 标签。

**[服务器终端]**

预期：HTML 中有 `name="renderer" content="webkit"`，且引用 `/assets/...`。

- 标签没有进入镜像：回第 7 节，随后 rebuild、up。
- 资源 404：检查是否仍在使用旧页面、资源是否被代理缓存或替换；使用新的 `lancheck` 参数重新打开首页并核对服务器日志。

#### 10.5.1 已知为 Chrome 86 时，先处理两个明确的运行时缺口

现场 UA 含 `Chrome/86.0.4240.198 ... QIHU 360ENT`。这指向 Chromium 86；UA 仍不等同于实际能力检测，但当前源码和构建产物中已经发现足以解释白屏的调用：

| 位置 | Chrome 86 上的影响 | 本节处理 |
| --- | --- | --- |
| `src/main.tsx` 首次渲染的 `messages.at(-1)`，以及曲线、调优、导航中的其他数组 `.at()` | 该方法不存在时，即使消息列表为空也会抛异常，React 无法完成首次渲染。 | 在应用模块执行前补齐 `Array.prototype.at`。 |
| `react-markdown` 及其依赖使用的 `Object.hasOwn()`；现有 `react-*.js` 中有此调用 | 已有 AI 消息或新回复进入 Markdown 渲染时可能再次报错。 | 同时补齐 `Object.hasOwn`。 |
| 页面高度及输入框高度使用的 `dvh` | 旧内核不能识别，可能导致布局或长消息输入框异常。 | 增加 `vh` 回退，保留新浏览器的动态高度。 |

`Array.prototype.at` 从 Chrome 92 起支持，`Object.hasOwn` 随 Chrome 93 引入，`dvh` 从 Chrome 108 起支持。[V8：at](https://v8.dev/features/at-method)、[V8 9.3](https://v8.dev/blog/v8-release-93)、[Chrome 团队：视口单位](https://web.dev/blog/viewport-units)

**建议沿用现有 Windows 浏览器，在服务器上做下面这个不新增 npm 依赖的兼容补丁。** `build.target` 只负责语法转换，不会补齐上述运行时方法，因此必须同时执行 10.5.3 和 10.5.4。[Vite 6 浏览器兼容说明](https://v6.vite.dev/guide/build#browser-compatibility)

本节使用当前包内的构建依赖，可离线重建。保留已经生效的 403 修复、网段白名单和 Origin/token 校验。这里的操作仅以 Chromium 86 为兼容目标，不是 IE/Trident 兼容方案。

#### 10.5.4 在 HTML 中先加载两个兼容方法

**[服务器终端]** 编辑 `source/apps/dashboard/index.html`。在 `</head>` **前面**插入以下完整片段；已有的 renderer 标签、页面标题和 `/src/main.tsx` 入口保留：

```html
<script id="chrome86-compat">
(function () {
  'use strict';
  if (typeof Array.prototype.at !== 'function') {
    Object.defineProperty(Array.prototype, 'at', {
      configurable: true,
      writable: true,
      value: function (index) {
        if (this === null || this === undefined) {
          throw new TypeError('Array.at requires a value');
        }
        var items = Object(this);
        var length = Math.min(Math.max(Math.trunc(+items.length) || 0, 0), 9007199254740991);
        var offset = Math.trunc(+index) || 0;
        if (offset < 0) offset += length;
        return offset < 0 || offset >= length ? undefined : items[offset];
      }
    });
  }
  if (typeof Object.hasOwn !== 'function') {
    Object.defineProperty(Object, 'hasOwn', {
      configurable: true,
      writable: true,
      value: function (object, key) {
        return Object.prototype.hasOwnProperty.call(object, key);
      }
    });
  }
})();
</script>
```

这是随首页发送的普通脚本，**不要加 `type="module"`、`async` 或 `defer`**。它必须在 React 和 Markdown 模块执行前完成；放进组件内部或入口文件末尾不能保证这个顺序。已有原生方法时不会覆盖。这里仅补充本应用使用的数组 `at`，不是为所有类型添加完整 ES 新特性。

不需要在内网执行 `npm install`，也不依赖外网 CDN。现有写请求已经为 `crypto.randomUUID()` 保留 `crypto.getRandomValues()` 回退，继续保留它，以支持通过普通 HTTP 的服务器 IP 访问。
